# Privacy statement — ELF//SHELL

ELF//SHELL does not collect or transmit analytics, telemetry, crash reports, browsing history, page contents, or personal information to a developer-controlled server. It has no developer-controlled server. Scripts, styles, wallpaper and launcher images are included in the extension package.

Firefox extension-local storage holds local notes, preferences, quick-link URLs, editable search templates and optionally saved sets of tab URLs and duplicate-tab recovery URLs until reopened or manually cleared. These recovery URLs may contain private query parameters. This storage is not encrypted. A JSON export includes this information. Users should avoid storing credentials or exporting private session URLs.

The extension uses `theme`, `search` and `storage` for browser appearance, user-initiated search and local settings; `scripting` and `activeTab` support optional website integration. The `tabs`, `sessions`, `bookmarks` and `history` permissions are optional, explained in the interface and revocable. The optional `https://*/*` declaration permits requests for individual HTTPS publication access (RSS/Atom), individual-site spelling, or broader HTTPS site access for the independently selected browser-wide cursor and offline spelling modes. **Broad HTTPS access is not granted on installation.** A user must select browser-wide modes and explicitly approve Firefox's permission request from Station configuration. Denying permission leaves browser-wide integration inactive. Existing RSS grants are not silently converted into spelling opt-in.

Searches submitted through Firefox or a custom bang, quick links clicked by the user and websites restored from saved sessions necessarily contact the corresponding external service. Those services' own privacy policies apply. ELF//SHELL does not send anything to these services except in response to the user's chosen action, or periodic RSS feed checks after the user has opted into a subscription and granted its website access. These requests go directly to the chosen publication and disclose the normal connection information such as IP address to that publication. RSS checks omit cookies and referrer headers. No developer-controlled tracking service is involved.

RSS publication URLs, custom titles, groups, source status and recent article headlines and URLs are stored locally without encryption. JSON export contains subscriptions, but not cached headline data; OPML export contains feed addresses and names. Importing OPML does not contact those publications until the user separately grants permission.

Ayarime Memory Trace quotations are packaged in a local JSON asset and involve no external requests. Quote display preferences, favourites, pinned entries, category filters and rotation timestamp are stored in Firefox extension-local storage without encryption. JSON station exports include these quote preferences.

## Optional browser integration: cursors and spelling

**Defaults:** The original station-only cursor and per-site spelling behaviour remains in place. No website is checked for spelling or given a custom cursor merely because the add-on is installed. Broad integration requires choosing the relevant "Across approved HTTPS websites" setting and approving the **all-HTTPS host permission** in Firefox.

When cursors are enabled, a local extension content script applies packaged cursor images to eligible HTTPS web pages. It reads the selected pointer style from local extension preferences; it does not inspect page text or make network requests. It cannot modify Firefox's own toolbars, browser settings pages or Linux desktop cursors.

When spelling is enabled, a separate local content script may read words in **compatible rich-text editors** on authorised sites to display custom underlines and a left-click suggestion menu. In ordinary textarea and text/search input fields, it checks **only the word directly left-clicked**, showing a local correction menu if the bundled dictionary considers the word incorrect. The native Firefox underline, right-click spelling entries and Undo remain enabled for these standard fields; extension suggestions and Firefox's native dictionary can sometimes differ. Word tokens are processed by the bundled British-English dictionary in a local background worker, never sent to a developer, external spellchecker or AI provider. Only words deliberately added to the personal dictionary are stored in extension-local, unencrypted storage. The native checker is disabled for a supported rich-text editor **only after** the local replacement engine responds successfully; failures restore it. Password, sensitive, read-only, code, unsupported fields and protected browser pages are excluded.

Both broad integration features can be turned off independently. Their background registrations are then removed, and existing eligible tabs are asked to restore their defaults; some inaccessible tabs may need reloading. Turning off integration modes does not automatically revoke host access that an RSS feed or another feature may still need. The separate **Revoke broad HTTPS access** control removes the wildcard grant while leaving separately granted site permissions intact. Firefox's add-on permissions settings provide another route to revoke website access. Changes are not applied to privileged Firefox pages, nor to extensions' other pages.

## Mozilla manifest disclosure (0.5.1)

`browser_specific_settings.gecko.data_collection_permissions.required` is `['none']`: the extension itself does not collect or transmit user data to a developer, analytics provider, or its own servers. Users can **optionally** authorise direct HTTPS fetches to their selected public RSS/Atom publishers. The destination sees the usual network request/IP address, but the extension does not relay browsing history, personal notes, or quick links to those publishers. Redirects are refused. As with any browser, manually opening search results or quick links contacts the selected website.
